# 구현 확인 기록 (2026-10-29)

## 현재 검증 결과

- 자동 시험 17개 통과. Telegram 자동 시험의 외부 호출은 대역을 사용한다.
- 사용자 보고로 확인: 실제 Telegram 편집자 시험 메시지와 Windows 오른쪽 아래 Chrome 팝업 모두 수신.
- 사용자 보고로 확인: 전체 일정 변경·최종 마감 확인·팬 안내, 연락 빈도 변경, 처리 실패·복구 절차. 상세 근거와 범위는 MANUAL_CHECKS.md를 따른다.
- 실제 두 Telegram 방의 연결 상태는 로컬 앱에서 확인했다. 이름·사진·소개를 모두 직접 확인했다는 별도 사용자 보고는 없으므로 해당 항목을 일괄 통과로 기록하지 않는다.
- 실제 집필 지속 효과와 지연 기간 동안의 하루 단위 발송 횟수·평소 빈도 복귀에 대한 장기 관찰은 미수행이다. 관련 상태 계산은 자동 시험으로 검증했다.

## 자동 시험과 화면 확인의 범위

- 일정 변경의 사용자 확인 전 보류, 전체 날짜 이동, 취소, 완료 처리, 오래된 제안 거절, 중복 처리 방지.
- 팬의 빈도·허용 시간대·지연 규칙, 저장·재시작, 실패 후 최신 상태로 재개.
- 고정 Telegram 일정 안내와 브라우저 알림의 개별 활성화 및 예약 갱신.
- 별도 시험 브라우저에서 주요 UI 흐름과 JavaScript 오류 없음 확인.
- 앱 알림함 도착·읽음·새로고침 유지, 시스템 팝업 요청의 브라우저별 처리·두 탭 중복 방지·과거 알림 미재생을 별도 시험했다. 실제 Windows 표시 성공은 위의 사용자 보고로 구분했다.
- 로컬 HTTP 응답과 다른 사이트 요청 차단, .env 및 개인 데이터의 HTTP 접근 차단 확인.

## 제출물 검사 후 회귀 시험

기존 시험 14개는 통과했으나 추가한 회귀 시험 3개는 수정 전 실패했다. 수정 후 전체 17개가 통과했다.

- 한국 시간의 월요일~일요일을 기준으로 다음 주 요일을 계산한다. 월~일 각각에서 다음 주 월요일과 일요일을 검사했다.
- Telegram 일정 안내가 켜진 상태에서 허용 시간대를 변경하면 공유 고정 안내 시각의 이동도 먼저 제시하고, 확인 후 적용하며 취소 시 유지한다.
- 공유 고정 안내 시각 변경으로 Telegram 허용 시간대를 우회하지 못하게 한다. 다른 방에서 설정을 바꿨다면 오래된 설정 제안도 그대로 적용하지 않는다.

## 비밀정보 검사와 실행 한계

- 검사 시점 GitHub main 이력 21개 커밋의 텍스트에서 일반적인 Telegram·Google·OpenAI·GitHub 키 및 개인키 패턴 발견 없음. 실제 .env가 Git 이력에 추적된 사례 없음.
- .env와 .data/state.json은 Git 제외 대상이다. 키 패턴 검사는 모든 형태의 비밀정보 부재를 보장하지 않는다.
- Telegram은 로컬 실행 프로그램을 켜두어야 한다. 브라우저의 새 예약 알림은 앱 탭도 열려 있어야 하며 원격 Web Push 구현은 아니다.
- 실제 봇을 사용하는 두 번째 프로그램을 동시에 실행하면 polling이 충돌하므로, 자동 시험은 임시 상태·대역 호출을 사용한다.
