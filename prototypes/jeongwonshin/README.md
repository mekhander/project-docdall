# 소재 찾기 (whattowrite) P0 프로토타입

러프한 아이디어를 AI 편집자와의 인터뷰로 파 들어가 "출판 기획서 한 건"으로 만드는 프로토타입입니다.
명세: `docs/specs/jeongwonshin-whattowrite.md` (P0 항목만 구현: 7개 차원 인터뷰, 기획서 카드, 확정, 저장과 이어하기)

> 주의: 실제 AI(Claude) 연결은 API 키가 있어야 작동합니다. 테스트는 키 없이 가짜 AI로 돌아갑니다.

## 실행 방법 (처음 한 번만 하는 준비 + 실행)

### 1. 터미널을 열고 이 폴더로 이동
터미널은 컴퓨터에 글자로 명령을 내리는 창입니다. (맥: Spotlight 검색 `터미널`)
아래 명령은 이 폴더에서 실행해야 하므로 먼저 이동합니다.
```
cd ~/Desktop/kaist/2-2.ai-business/teamproject/project-docdall/prototypes/jeongwonshin
```

### 2. 이 프로젝트 전용 파이썬 환경 만들기
```
/opt/anaconda3/bin/python3 -m venv .venv
```
이유: 이 프로젝트에 필요한 프로그램을 이 폴더 안에만 설치해서, 컴퓨터의 다른 것과 섞이지 않게 합니다. (`.venv` 폴더가 생깁니다)

### 3. 필요한 프로그램 설치
```
.venv/bin/pip install -r requirements.txt
```
이유: Claude를 부르는 데 쓰는 Anthropic 공식 도구(SDK)를 설치합니다.

### 4. API 키 넣기 (실제 AI를 쓰려면)
1. https://console.anthropic.com 에 가입/로그인한 뒤 Settings -> API Keys 에서 키를 만듭니다.
   사용량만큼 요금이 나가므로 Billing 에서 크레딧 충전이 필요합니다.
2. 예시 파일을 복사해 `.env` 파일을 만듭니다.
   ```
   cp .env.example .env
   ```
3. `.env` 파일을 열어 `your_key_here` 자리에 받은 키를 붙여 넣고 저장합니다.

이유: 키는 비밀번호와 같아서 코드나 git에 올라가면 안 됩니다. `.env` 파일은 git이 무시하도록 설정돼 있어 올라가지 않습니다. 키를 채팅이나 문서에 붙여 넣지 마세요.

### 5. 서버 켜고 열기
```
.venv/bin/python server.py
```
브라우저에서 http://localhost:8000 을 엽니다. 끄려면 터미널에서 `Ctrl + C`.
인터뷰는 `data/` 폴더에 저장되고, 같은 브라우저로 다시 열면 이어집니다.

### 6. 테스트 돌리기 (키 필요 없음)
```
.venv/bin/python -m unittest discover -s tests -v
```
마지막에 `OK` 가 나오면 규칙·저장·확정 조건이 설계대로 동작하는 것입니다.

## 작동 확인 방법 (사람이 브라우저에서 직접)

명세의 "손으로 해 보는 확인" 3가지입니다. 1번은 실제 AI로 꼭 직접 해 봐야 합니다.

1. 타깃 독자에서 추궁이 나오는지
   1. 서버를 켜고 화면에서 아이디어를 적어 필요성·목적, 저자의 고유성 질문에 성실히 답해 타깃 독자 질문까지 갑니다.
   2. 타깃 독자 질문에 `20~30대 직장인이요` 라고 답합니다.
   3. 오른쪽 카드의 타깃 독자 배지가 "보완 중"이 되고, 편집자가 더 구체적으로 되묻는지 확인합니다.
2. 닫았다 열어도 이어지는지
   1. 세 번째 차원(타깃 독자)쯤에서 브라우저 탭을 닫습니다.
   2. 같은 브라우저로 http://localhost:8000 을 다시 엽니다.
   3. 카드 내용이 그대로 있고, 편집자의 마지막 질문이 타깃 독자 질문인지 확인합니다.
3. 한 줄 콘셉트가 보류면 확정이 막히는지
   1. 첫 질문("지금 가진 것을 알려 주세요")은 건너뛸 수 없으니 아이디어를 한 줄 적습니다. 그다음 각 차원에서 `이 질문은 나중에`를 눌러 한 줄 콘셉트까지 보류합니다.
   2. "다시 볼지, 이대로 정리할지" 질문에서 `이대로 정리하기`를 누릅니다.
   3. `출판 기획서 확정` 버튼이 눌리지 않고, 이유 안내가 보이는지 확인합니다.

## 구조

| 파일 | 하는 일 |
|---|---|
| `server.py` | 서버. 화면 제공과 JSON API |
| `interview.py` | 한 턴의 순서(저장 -> 판정 -> 다음 행동 -> 말하기)를 이어 붙임 |
| `rules.py` | 다음 행동을 정하는 규칙. AI·파일을 쓰지 않는 순수 코드 |
| `rubric.py` | 7개 차원의 확인할 것, 약한 신호, 추궁 방향, 예시 |
| `editor_ai.py` | Claude 호출(판정, 편집자 말), 테스트용 가짜 AI |
| `store.py` | `data/<id>.json` 저장과 불러오기 |
| `envfile.py` | `.env` 읽기 |
| `public/index.html` | 화면 (채팅 + 기획서 카드) |
| `tests/` | 자동 테스트 |
| `.env.example` | 키 자리 예시 (실제 `.env`는 직접 만듦) |

원칙: 무엇을 물을지는 코드(rules.py)가 정하고, AI는 판정과 문장 쓰기만 합니다.
