# HW6 회고 초안 — 박성규

상태: 대화와 실제 확인 기록에 근거한 초안. 제출 전 본인 표현으로 검토한다. 확인하지 않은 경험은 만들어 쓰지 않는다.

## 1. WhyTree를 만들면서

Docdall의 대상은 책을 반드시 써야 할 분명한 목적이 있는 사람보다는, 한 번쯤 자기 책을 갖고 싶다는 로망이 있지만 시작과 지속이 어려운 사람으로 정했다. “왜 책을 완성하고 싶은가?”를 위로 물어보며 버킷리스트 달성과 성취감, 내 경험에 가치를 부여하는 일, 지금까지의 삶과 전문성을 인정받는 목적까지 생각하게 됐다.

특히 “내 경험을 정리하는 것”이 최종 목적이 아니라 “나의 경험에 가치를 부여하는 것”의 수단이라는 구분을 대화 중 직접 바로잡았다. “당신의 이야기를 읽고 싶다. 나에게 필요하다”는 독자의 응원도 다른 사람에게 기여한다는 느낌과 연결했다.

슬라이드 변환에서는 내 단어와 노드만 유지하고, 관계를 AI가 새로 만들지 않도록 요청했다. Markdown은 실선 계층과 점선의 부가적 연결을 나눠 표현했다. 이번에는 Markdown 변환 결과에서 내가 별도로 수정한 사례는 없었다. 따라서 AI의 변환 오류를 고쳤다는 사례를 억지로 만들지는 않았다.

## 2. grill-me를 하면서

“알림을 어떤 채널로, 누가, 언제 보내며 답장을 어떻게 처리할 것인가?”를 구체화하는 질문이 단순한 리마인드 아이디어를 실제 기능으로 바꾸었다. 브라우저는 고정 시간의 일정 안내를 맡고, 텔레그램에서는 편집자와 팬을 서로 다른 두 방으로 구분하기로 했다. 편집자는 일정과 재약속을, 팬은 기대와 응원을 담당한다.

추천을 수용한 사례는 두 역할의 방을 분리하는 방식이다. 사용자가 누구와 대화하는지 명확하게 구분할 수 있도록 이름·사진·소개도 구별하기로 했다.

추천을 수정하거나 거절한 사례도 있다. 처음에는 지연 중 팬의 말투만 강화하고 빈도를 유지하자는 추천에 대해 말투와 빈도를 모두 강화하자고 답했다. 이후 논의를 거쳐 지연 중 팬은 하루 한 번으로 제한했다. 편집자가 마감 이후 매일 확인하는 추천은 받아들이지 않고 마감 다음 날 한 번만 알리도록 정했다.

## 3. 명세서를 만들면서

P0에는 실제 텔레그램 연결, 편집자와 팬의 역할 구분, 일정 안내, 대화로 빈도 변경, 사용자 확인 후 전체 일정 조정, 공통 상태와 실패 복구를 넣었다. 이번 기능에서 사용자가 실제로 연락을 받고 답하며 집필 일정을 다시 약속하는 흐름을 확인하는 데 필요한 항목들이기 때문이다.

추가 이메일 전달과 다양한 빈도 표현은 P1, 외부 AI 연결과 문자·카카오톡·다중 사용자 지원은 P2로 미뤘다. 출간기획서·목차·페르소나 생성은 앞 단계라고 가정하고 예시 데이터를 사용했다. 현재 버전은 외부 AI 모델 없이 준비된 문구와 규칙으로 동작한다.

가장 여러 차례 조건을 정한 부분은 마감 지연 처리였다. 한 챕터만 옮기는 것이 아니라 이후 미완료 챕터와 최종 마감이 얼마나 늦어지는지 보여주고, 사용자 확인 후에만 전체 일정을 갱신하도록 했다. 팬도 같은 확정 상태를 보고 편집자에게 지연 소식을 들었다고 말하게 했다.

## 4. 구현하고 달라진 점

처음 브라우저 알림 시험에서는 화면 중간 아래에 안내 메시지만 잠깐 나타났다. 내가 원한 것은 Windows 오른쪽 아래의 실제 팝업이었다. 앱 안의 메시지, 브라우저의 알림 요청, Windows의 실제 표시가 서로 다른 단계임을 확인했다. Chrome의 사이트 권한은 허용되어 있었지만 Windows의 Chrome 알림은 꺼져 있었다.

이 경험을 명세서의 앱 알림함 구분(267행), 실제 시스템 팝업 확인 요구(280행)에 반영했다. 기존 다른 사이트의 알림까지 받고 싶지는 않았기 때문에 사이트별 허용을 구분하는 방법과 Telegram 고정 일정 안내도 추가했다(290행). 해당 줄 번호는 이 초안 작성 시점의 docs/specs/park-sunggyu-reminder.md 기준이다.

최종 시험에서는 Telegram 메시지와 Windows Chrome 팝업 모두 도착한 것을 직접 확인했다. 전체 일정 변경과 팬 안내, 빈도 변경 및 실패·복구 절차도 확인했다. 자동 시험 14개 통과와 내가 실제로 확인한 결과는 별도로 기록했다. 알림이 실제로 꾸준한 집필이나 책 완성에 도움이 되는지는 이후 사용하면서 확인해야 한다.
