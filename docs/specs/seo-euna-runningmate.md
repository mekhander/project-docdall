# Spec — 러닝메이트 (runningmate)

- 제품: 닥달 (DocDall)
- 작성: 서은아 (seo-euna)
- 날짜: 2026-10-29
- 출발점: WhyTree [`docs/whytree/seo-euna.md`](../whytree/seo-euna.md)의 씨앗 "동기부여" 아래 새 노드 "러닝메이트" (점선)
- 방법: `/grill-me`로 정했다. 구현하면서 바뀌는 것이 있으면 이 문서를 먼저 고친다.

## 1. 한 문장

같은 시기에 책을 끝내려는 4~7명이 러닝메이트가 되어, 서로 언제 얼마나 썼는지와 목차 기준 진행률을 본다. 각자 공개한 주간 약속이 혼자 한 다짐보다 강한 강제성이 된다.

## 2. 누구를 위한 것이고, 문제는 언제 드러나는가

- **누구**: 책을 처음 쓰는 사람 중, 글감은 있지만 책 구성을 못 짜는 사람, 또는 글감이 아직 모호한 사람. 이미 글을 1편 이상 써 둔 사람이다.
- **문제가 드러나는 순간**: 3일 이상 멈췄다가 앱을 다시 열었을 때. "또 못 끝내겠지" 하고 다시 닫는 순간이다.
- **왜 멈췄나**: 귀찮아서. 스스로 시작한 선택을 스스로 지키라고만 하면 강제성이 약하다. 같은 목표를 가진 사람들이 러닝메이트가 되어 주는 것이 필요하다.

## 3. 어느 WhyTree 노드를 위한 것인가

러닝메이트 (새로 찾은 how, 점선) → 동기부여 [씨앗] → 꾸준히 쓰는 습관 = 책 완성 → 시작한 책을 끝까지 해낸 경험 갖기

"글쓰기 독촉"과의 경계: 독촉은 앱 **밖에서** 불러 앱을 열게 하는 일(알림, 푸시)이다. 러닝메이트는 앱을 **연 뒤에** 다시 쓰고 싶게 만드는 일만 한다.

## 4. 사용자가 하는 일 (단계별)

1. 처음 열면 최소 기획서를 쓴다: 책 제목, 타겟 독자 한두 문장, 완성 목표일.
2. 목차의 꼭지 제목을 직접 입력한다.
3. 닉네임을 정하고, 그룹 코드를 새로 만들거나 받은 코드로 들어간다.
4. 이번 주 약속을 정한다: "이번 주 N일 쓰기" (1~7).
5. 꼭지를 골라 글을 쓰고 저장한다. 날짜와 글자 수가 자동 기록된다.
6. 그룹 보드에서 메이트들의 쓴 날짜, 글자 수, 진행률, 주간 약속 현황을 본다.
7. 3일 이상 쉬었다가 다시 열면 "돌아옴 화면"을 보고, "지금 쓰기"로 바로 쓰기 시작한다.

## 5. 규칙

| 항목 | 규칙 |
|---|---|
| 그룹 크기 | 최대 7명. 4명 미만이어도 시작할 수 있고, "메이트를 더 초대하세요"를 보여 준다. |
| 목표일 차이 | 들어가려는 그룹에 내 목표일과 30일 넘게 차이 나는 메이트가 있으면 경고한다. 참여는 막지 않는다. |
| 한 주 | 월요일~일요일 |
| 주간 약속 | 주 1~7일. 주중에 바꾸면 다음 주부터 적용된다. |
| 쓴 날 | 그날 저장한 글이 합쳐서 600자 이상(공백 포함)이면 쓴 날이다. 20분 집중해서 지어 쓰는 양을 600~1,000자로 어림하고 그 아래쪽을 골랐다. 설정값으로 둔다. |
| 진행률 | 600자 이상 쓴 꼭지 수 ÷ 전체 꼭지 수. 한 꼭지에 쓴 글을 모두 합쳐 600자 이상이면 그 꼭지를 센다. (직접 점검 후 변경: 처음에는 "글이 1편 이상 있는 꼭지"였는데, 몇 글자만 저장해도 진행률이 올라가서 "쓴 날"과 같은 600자 기준으로 맞췄다.) |
| 돌아옴 기준 | 마지막 저장 후 3일 이상 지나서 열었을 때. 설정값으로 둔다. |
| 메이트에게 보이는 것 | 쓴 날짜, 글자 수, 진행률, 주간 약속 현황. 본문은 보이지 않는다. |

**돌아옴 화면** (순서대로)

1. "N일 만이에요" (탓하는 말 없이)
2. 그동안 메이트들이 쓴 기록: 누가, 며칠, 얼마나
3. 이번 주 내 약속 현황: 예) 0/3, 남은 날 4일
4. "지금 쓰기" 버튼 하나

## 6. 우선순위

### P0: 반드시 만든다

- 최소 기획서(책 제목, 타겟 독자, 완성 목표일)와 목차 직접 입력
- 글 쓰기·저장: 꼭지 선택, 날짜와 글자 수 자동 기록. 본문은 내 브라우저에만 저장한다.
- 닉네임 + 그룹 코드로 참여 (로그인 없음), 인원 안내, 목표일 경고
- 그룹 보드: 메이트들의 쓴 날짜, 글자 수, 진행률, 주간 약속 현황. 진짜 공유(Supabase).
- 주간 약속 설정과 현황
- 돌아옴 화면
- DB 연결이 안 될 때의 동작 (8절)
- 테스트용 날짜 바꾸기: 주소에 `?today=YYYY-MM-DD`를 붙이면 그날로 친다.

### P1: 시간이 되면

- **AI 가상 독자** 1~2명
  - 기획서의 타겟 독자로 페르소나를 만든다.
  - 앱을 열었을 때 "내 독자" 영역에 보인다. 예: "작가님 언제 돌아와요", "작가님 다음 편 궁금해요"
  - 메이트 보드와 섞지 않고, AI라고 표시한다.
  - 내 최근 글을 읽고 독자로서의 감정 반응과 궁금한 점 질문 1개만 한다. 문장을 고치거나 다음 내용을 제안하지 않는다.
- 목표일 30일 이내 기준 자동 매칭

### P2: 나중에

- 푸시 알림 (글쓰기 독촉 기능으로 넘긴다)
- 블로그·브런치 연동
- 벌칙·내기

## 7. 범위 밖

- 앱 밖에서 부르는 모든 것 (알림, 푸시, 이메일): 글쓰기 독촉 기능의 몫
- 글이 0편인 사람의 주제 찾기: 내 글감 구체화 기능의 몫
- 목차를 함께 짜 주기: 구성 기능의 몫
- AI가 본문을 쓰거나 고치는 것: 어떤 우선순위에서도 하지 않는다

## 8. 기술과 실패 시 동작

- **형태**: 서버를 따로 두지 않는 웹페이지(HTML + JavaScript). `prototypes/seo-euna/`에 둔다.
- **공유 DB**: Supabase. 본문은 올리지 않고 닉네임, 그룹, 날짜, 글자 수, 진행률, 주간 약속만 올린다. 행 단위 보안(RLS)을 켠다.
  - (빌드 후 추가) 테이블은 RLS로 모두 막고, 브라우저는 정해진 DB 함수로만 읽고 쓴다. 그룹에 들어갈 때 받은 비밀 토큰이 있어야 내 기록을 쓸 수 있다. 같은 그룹 안에서 닉네임은 겹칠 수 없다.
  - (빌드 후 추가) "최대 7명"과 "약속은 다음 주부터"는 브라우저가 아니라 DB 함수가 강제한다. 지난주에 정한 약속이 이번 주에도 이어지고 있으면, 그것도 "이번 주 약속이 있다"로 보고 새 약속은 다음 주부터 적용한다.
- **키 관리**: Supabase URL과 publishable 키는 `prototypes/seo-euna/config.js`에 두고 `.gitignore`에 넣는다. 저장소에는 빈 값의 `config.example.js`만 올린다.
- **DB 연결이 안 될 때**: 글쓰기와 저장은 그대로 된다. 보드에는 "메이트 현황을 불러오지 못했어요"만 표시한다. 올리지 못한 기록은 연결이 돌아오면 올린다.
- **알려진 한계**
  - P0의 강제성은 테스트할 아는 사람 몇 명 사이에서만 검증된다.
  - 로그인이 없다. 토큰은 브라우저에만 있어서, 브라우저 데이터를 지우면 같은 그룹에 같은 닉네임으로 다시 들어갈 수 없다(빌드 후 수정: 처음에는 "다른 사람인 척할 수 있다"고 적었지만, 토큰 때문에 남의 기록은 쓸 수 없다).
  - 본문은 브라우저에만 있어서, 브라우저를 바꾸면 따라오지 않는다.
  - `?today=`로 저장한 글은 그 날짜에 쓴 것으로 기록된다. 점검이 끝나면 테스트 그룹을 지운다.

## 9. AI 모델

- **P0**: AI를 쓰지 않는다.
- **P1 (AI 가상 독자)**: `claude-haiku-5-5`. 짧은 메시지를 빠르고 싸게 만든다.
  - API 키는 브라우저에 두지 않고, Supabase Edge Function의 비밀값으로 두고 거기서 호출한다.
  - 본문은 호출할 때만 보내고 저장하지 않는다.
  - **실패할 때**: 응답이 없거나 5초를 넘기면, 미리 써 둔 격려 문구 중 하나를 보여 준다. 오류 화면은 보이지 않는다.

## 10. 직접 확인하는 점검

1. **공유와 비공개**: 일반 창과 시크릿 창에서 같은 그룹 코드로 두 사람(A, B)이 들어간다. A가 글을 저장하면 B의 보드에 A의 날짜, 글자 수, 진행률이 보인다. 본문은 B의 화면 어디에도, Supabase 테이블에도 없다.
2. **돌아왔을 때**: A가 글을 저장한 뒤, 주소에 `?today=`로 4일 뒤 날짜를 붙여 연다. "4일 만이에요" 화면이 나오고, 그사이 B가 쓴 기록이 보인다.
3. **숫자 계산**
   - 목차 4꼭지에 각각 700자, 600자, 599자를 저장하고 1꼭지는 비워 두면 진행률이 50%다. 599자 꼭지는 세지 않는다.
   - 약속이 주 3일이고 2일을 썼으면 2/3이다.
   - 하루에 599자만 쓴 날은 쓴 날로 세지 않고, 600자는 센다.
