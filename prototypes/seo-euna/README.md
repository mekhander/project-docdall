# 러닝메이트 P0 (seo-euna)

스펙: [docs/specs/seo-euna-runningmate.md](../../docs/specs/seo-euna-runningmate.md)

같은 시기에 책을 끝내려는 4~7명이 서로의 쓴 날짜, 글자 수, 목차 진행률, 주간 약속을 보는 웹페이지입니다.
본문은 내 브라우저에만 저장되고, 서버(Supabase)에는 올라가지 않습니다.

## 파일

| 파일 | 내용 |
|---|---|
| `index.html`, `style.css`, `app.js` | 화면: 기획서·목차 → 그룹 → 보드, 주간 약속, 쓰기, 진행률, 돌아옴 화면 |
| `logic.js` | 규칙 계산 (600자, 진행률, 주간 약속, 3일 돌아옴, 목표일 30일 경고) |
| `supabase/schema.sql` | 테이블 4개, RLS, DB 함수 6개 |
| `config.example.js` | 키 템플릿. 복사해서 `config.js`를 만든다 (`config.js`는 커밋되지 않음) |

## 처음 한 번: 설정

1. Supabase 프로젝트를 만들고 SQL Editor에서 `supabase/schema.sql`을 실행한다.
   (은아의 프로젝트 `docdall-runningmate`에는 이미 적용되어 있다.)
2. `config.example.js`를 `config.js`로 복사하고, Project Settings > API의 URL과 publishable 키를 넣는다.
   publishable 키는 브라우저에 노출되도록 만든 공개용 키다. 그래도 저장소에는 올리지 않는다.

Supabase 보안 점검(advisors)에 "anon이 SECURITY DEFINER 함수를 실행할 수 있다"는 경고가 6개 나온다.
테이블을 모두 막고 정해진 함수로만 드나들게 한 설계라서 의도한 것이다. 쓰기 함수는 참여할 때 받은 토큰을 확인한다.

## 실행

```bash
cd prototypes/seo-euna
python3 -m http.server 8765
```

브라우저에서 http://localhost:8765 를 연다.
두 사람을 흉내 내려면 **일반 창과 시크릿 창**을 쓴다(저장소가 따로라서 다른 사람이 된다).

주소에 `?today=2026-11-01`처럼 붙이면 그날이 오늘인 것처럼 동작한다. 이 날짜로 저장한 글은 그날 쓴 것으로 기록된다.

## 직접 확인하는 점검 (스펙 10절)

### 1. 공유와 비공개
1. 일반 창(A): 기획서와 목차 입력 → "그룹 만들기" → 그룹 코드를 적어 둔다.
2. 시크릿 창(B): 기획서 입력 → 코드 입력 → "확인" → "참여하기".
3. A에서 글을 저장하고, B를 새로고침한다.
4. **확인**: B의 보드 A 줄에 오늘 칸 글자 수와 진행률이 보인다. A의 본문은 B 화면 어디에도 없다.
   Supabase Table Editor의 `daily_logs`에도 날짜와 글자 수만 있다.

### 2. 돌아왔을 때
1. A: `?today=2026-10-28`로 열고 글을 저장한다.
2. B: `?today=2026-10-30`으로 열고 600자 넘게 저장한다.
3. A: `?today=2026-11-01`로 연다.
4. **확인**: "4일 만이에요" 화면에 B가 "1일 · N자"로 보이고, 내 약속 현황과 "지금 쓰기" 버튼이 있다.

### 3. 숫자 계산
1. 목차를 4꼭지로 만들고, 월요일 날짜로 열어 주 3일 약속을 한다.
2. 월요일 700자(1장), 화요일 599자(3장), 수요일 600자(2장)를 각각 그 날짜로 저장한다. 4장은 비워 둔다.
3. **확인**: 진행률 50% (2/4꼭지, 599자인 3장은 세지 않음), 약속 2/3일. 화요일(599) 칸은 초록이 아니고, 수요일(600) 칸은 초록이다.
